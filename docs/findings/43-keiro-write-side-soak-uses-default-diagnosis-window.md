# Keiro write-side soak uses the default diagnosis window after a shorter duration override

Status: reproduced in the local Kenshou scenario and repaired in source; the clean shortened cell replay verified the effective window. Owner is this repository. No Keiro runtime bug report follows from this run.

The clean released-cohort alpha cell run `01a0ef11-a09f-75f6-a554-1c1e93be41e5` executed nested run `01a0ef11-50b8-7113-8e21-19926af2ea98` with `soak.duration-minutes=5`. The workload ran for five minutes, but its leak diagnosis retained the reduced scenario's static 20-minute steady window, from second 5 to second 1205. It therefore reported `insufficient-data` after collecting only about 299 seconds of points. The same run failed three business checks, which cannot be attributed to a runtime defect from this shortened, mismatched configuration alone.

`Kenshou.Suite.Keiro.Command.SteadyState` derived the measurement duration from the knob while the registered `PhasePlan` and `RunContext.steadyWindow` kept the default 1200-second duration. The scenario accepts overrides down to one minute. `Kenshou.Diagnose.Leak.judgeLeaksWithWindow` now accepts the effective measurement window, and both Keiro write-side soak variants use it. The diagnosis and Keiro package tests pass. The five-minute historical result remains excluded.

The revised scenario sealed and verified on clean released payload `ec6be15` as alpha cell run `01a0efcb-3343-70c7-879c-66485b85e2bc`, [nested run `01a0ef66-959a-7183-a9aa-3e4bed4fc7da`](../verification/runs/keiro/2026/09/01a0ef66-959a-7183-a9aa-3e4bed4fc7da.md). The diagnosis window is now exactly seconds 5–305 and the measurement steady interval is 300 seconds. All ten business checks passed at 20 commands/second: the workload quiesced, each transfer stage and bonus effect matched, balances and async activity matched, and no dead letters remained. The run's overall `failed` outcome came from a suspected router-worker heap leak, consistent with the already filed `mori://shinzui/kiroku/okf/bug-reports/concepts/BUG-3`. The five-minute main-process heap probe lacked enough post-major-GC points, so this run validates the window repair and functional control but is not a full leak clearance.
