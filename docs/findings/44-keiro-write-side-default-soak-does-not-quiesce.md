# Keiro write-side default soak does not quiesce within the drain budget

Status: observed on the clean released cohort; attribution pending. No new owner-project bug report is justified until a controlled lower-rate run and explicit durable backlog counts distinguish overload from incorrect effects.

The planned 20-minute `keiro/command/soak/write-side-steady-state-reduced` run on alpha, verified cell run `01a0ef29-112a-7170-8e14-1e586ac1cb81` and [digest-linked nested run](../verification/runs/keiro/2026/09/01a0ef1a-d6e9-77d1-aefb-d43eb6460645.md), used durable PostgreSQL 18, the clean released payload, and its default 200 commands/second target. The scenario waited two minutes after stopping both writers, then failed `exactly-once-target-effects`, `inline-balances`, and `async-activity`. Source inspection shows the exact-effects verdict requires `awaitQuiescence` to complete inside that fixed budget; the run summary retained 15,075 transfer-debit events and 14,870 bonus events, but did not retain each pending-stage count or the quiescence flag. It cannot establish whether work was lost or simply backlogged.

The same run suspected post-major heap growth in process-manager and router workers, consistent with the already filed released-Kiroku publisher-retention defect `mori://shinzui/kiroku/okf/bug-reports/concepts/BUG-3`; that is tracked separately in [finding 1](1-keiro-write-side-worker-heap-growth.md). The high-rate business failures are not folded into that owner issue. The revised scenario now records each transfer stage, saga count, activity count, inline-balance check, and quiescence result. A [clean five-minute 20-command/s control](../verification/runs/keiro/2026/09/01a0ef66-959a-7183-a9aa-3e4bed4fc7da.md) passed all ten business checks and quiesced; its short duration and lower total load do not explain the twenty-minute default-rate failure. A same-seed twenty-minute lower-rate cell control is running before assigning ownership or proposing a throughput target.
